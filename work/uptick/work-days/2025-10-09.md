## Task Sessions Bug

So right now, `tasksession_labour_products` is a flag that will add the sell product of a task session to an invoice if the task meets a certain criteria (is type Time and Materials, etc). This means that creating a task session with a technician that has a sell product on a task will create an invoice line item with the sell product on the invoice. 

TLDR: it automatically populates line item data for task sessions.

Maddi's new labour modal enforces a new workflow where you would
- First create the tasksession
- Use the billable labour modal to automatically create a servicetask
- The invoice pulls the billable data from the servicetask

However, for customers with the `tasksession_labour_products` flag:
- The invoice will pull from the tasksession
- The invoice will also pull from the service task created by the billable labour
Resulting in duplicated data.

A clear way to fix this is to **remove the tasksession invoice line item creation logic** when creating the invoice. This is is a key change to this function that is used in many different places. It will affect the following:
- Invoice creation (intended)
- FES's `send_daily_email_summary` (unintended?)
- `autoclose_task` (unintended?)
- `task.get_unbilled_amount` -> used in dispatching (unintended?)

In summary, we can just remove this block of code
```python
if FeatureFlag.tasksession_labour_products.is_enabled:
	lineitems_tasksessions = []
	Task = apps.get_model("tasks", "Task")
	if task.charge_type == Task.CHARGE_TYPE.TIMEANDMATERIALS:
		lineitems_tasksessions = self.prepare_from_tasksessions(  # type: ignore[no-untyped-call]
			task, grouping == "product"
		)
	lineitems += lineitems_tasksessions
```

But I worry about the effects it will have on the above functions, as well as future cemented profitability calculations.
