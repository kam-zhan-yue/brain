## Product Description Bug
- The frontend is populated by a `tasks/:taskId/prepare_invoice/?query` api call
- The query is simply
```json
{
	include: 'product',
	grouping: 'product',
	uninvoiced: false,
}
```

The task api calls `InvoiceLineItem.objects.prepare_from_task`. I love this :(

It seems like the `invoicelineitem_description` on the `task.subtask_set` is being set incorrectly.

```shell
ipdb> subtask_1.invoicelineitem_description
'other labour rate'
ipdb> subtask_2.invoicelineitem_description
'other labour rate'
```

So, how is the `task.subtask_set` being set? What is a subtask?

A subtask has a billing contract. So it's created from a billing contract? How is the invoicelineitem set? That's set somewhere else.

That's set in `prepare_from_routine`

Alright so the problem is this code
```python
if billingcontract:
	visible_lis_for_routine = billingcontract.lineitems.filter(
		Q(all_routines=True) | Q(levels__in=[routine.routineservicelevel.type]),
		visible=True,
	)
	per_asset_bcli = visible_lis_for_routine.filter(
		type=BillingContractLineItem.RATE_TYPE.PER_ASSET
	).first()
	if per_asset_bcli:
		unit_product = per_asset_bcli.product
		unit_price = per_asset_bcli.unit_price
		description = per_asset_bcli.description
```

The code will try to find the line items where `levels__in=[routine.routineservicelevel.type]` and get the first one that is PER_ASSET

However, for routines with the same routine service level type, they will get the same line item, hence the same description. I think the issue goes further up. How are routines even created in the first place from a billing contract?

For the servicetask, we attach the billing contract line item product to the service task product. However, the subtask doesn't know this. There's no way for the subtask to get back the data from the billing contract line item.


Let's map out the flow from the start
- We have a billing contract with line items
- We create routines on the property
- We generate tasks from that routine
	- Generates servicetasks
	- Generates subtasks

So there is currently a routine on the property. 3007308

OH! The service tasks both point to the same routine! WTF!

The service task is getting the same subtask.... hence, they get the same description. Are there different subtasks? Probably

There are two service tasks, but one subtask. So they'd get the same subtask invoice line item description.

Each routine correlates to one subtask
For each routine's asset, there is one servicetask

The invoice lineitem is stored on the subtask.

But in the event of service tasks, we want to be showing the invoice line item on the service task, not the subtask.

Ok, so if they are billable, they should be getting it from the billing contract instead, probably.

How can we get it from the billing contract at this stage?

One potential solution is:
1. Add a new field called invoicelineitem_description on the service task
2. Populate it in `prepare_routine_servicetask_for_asset`
3. Fetch it in the `prepare_from_servicetasks` when making the invoice line items
