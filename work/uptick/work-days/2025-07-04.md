## Root Cause
Okie so if the Task has an invoice, it will go to `task.get_unbilled_amount` which will cause a longggg query.

It's this.
```python
def get_unbilled_amount(self) -> Decimal:
	lineitems = LineItem.objects.prepare_from_task(
		self, performed_only=True, uninvoiced_only=True
	)
	totals = [lineitem.calculate_subtotal() for lineitem in lineitems]
	return round_decimal(Decimal(sum(totals)), 4)
```


Seems like we were calling `get_unbilled_amount` twice. Removing one call ended up with
```
[workspace=default] 172.18.0.1:57294 [2025-07-04 12:20:06] "GET /api/v2/dispatches/prepare_for_task/?task=31418" SC200 588b 16.771s SQL12013 USER1 VERY_SLOW_DUR VERY_SLOW_SQL
```

Time is cut in half and queries went from 18007 to 12013. But we can do better.

It does `prepare_from_task` then `calculate_subtotal`.
- `calculate_subtotal` is a simple `round_decimal`, so nothing there


OHhhhh shiiiit. It will call `prepare_from_task` recursively. Chat we are cooked. I think in order to solve this, we need to understand this on a deeper level. Why are we doing this? What are we trying to accomplish. What is `prepare_from_task` doing?
