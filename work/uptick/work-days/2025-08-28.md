### Preferences

The problem is that previously, customers were able to make any and all preferences.

However, now we replace '.' with `_`

Why? I'm not entirely sure yet


Getting preferences will return us a JSON object


When we get back preference, we query the underscore directly.

```shell
In [15]: user.preferences.keys()
Out[15]: dict_keys(['apps', 'general', 'tasks_new_task_detail', 'service_dashboard_prefs'])
```

This is stored on the `ListFilterset` and queried on the `favouritesKey`

`favouritesKey` is split on the `:`
Which will allow us to drill into it

So we get 


There are:
- Users that created preferences like '5. Marcus'
- And could be users that created preferences like '5. what' which gets turned into '5__what'

So when we get back the preferences, we want to show the full thing despite there being `__`
- 5. Marcus
- 5__what

And, when we create, we want to be able to make either
- 5. Marcus
- 5__what

Ok so when we get the preference, we get it by the key. We use
```tsx
getPreference("apps.tasks.task_scheduler.forecast")
```


We use dots because of `object-path-immutable`
