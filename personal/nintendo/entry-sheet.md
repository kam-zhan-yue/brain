## 上記に対して、技術的に困難な課題は何だったのか、そのために何をしたのかを記入してください。(600文字以内) 

2年記念日のマルチプレイヤーゲームでは、選択によってストーリーが分岐し、エンディングが変化するシステムの実装に取り組んだ。同時に、このストーリーを複数のクライアントに同期させる必要があった。分岐するストーリーを実装するために、Inkを用いてストーリーロジックを記述した。そして、Axumのバックエンドと統合した。フロントエンドとの通信にはWebsocketsを利用した。Rustの相互排他と原子的な参照カウントを使用し、共有常態管理を実装した。サーバーのストーリーは複数のクライアントがお互いに上書きすることなく安全にやり取りできるようにした。これにより、サーバーを唯一の状態管理元として設計した。フロントエンドはプレゼンテーション層として機能するようになった。

また、3つのゲーム開発を総括していた際、コードベースは絶えず変更され、新機能やバグ修正を効率的にテストする方法がなかった。GitHub Actionsを用いたCIパイプラインを構築し、PRのマージごとに自動ビルドと配信を行うことにした。さらに、PRごとにウェブビルドを静的サイトにアップロードし、マージする前に変化内容を事前に確認できるようにした。Steamでのリリースを準備するために、CDを追加し、ビルドをSteamのベータ版ブランチと本番ブランチに公開した。テストが大幅に強化され、開発サイクルを短縮した。

When building a multiplayer game for my 2 year anniversary, I wanted to implement a story game with branching dialogue and different endings. The choices made by the players could alter the ending of the game. At the same time, this story needed to be synced to two different clients through networking. To implement the branching dialogue and support multiple endings, I wrote the story logic in a narrative engine called Inky. I then integrated this with the backend server, which I wrote using Rust and a web framework called Axum. I used websockets to connect the frontend to the server, and used atomic reference counting (arc) and mutual exclusion (mutex) to ensure that multiple clients could safely interact with one story without overwriting one another. This allowed the story on the server to act as a Single Source of Truth (SSOT) and the frontend acted as a presentation layer.

When overseeing production for the three games, there were constant changes to the codebase and no efficient way to test new features and bugfixes. Hence, I implemented a CI pipeline using Github actions to build and upload the game whenever pull requests were merged. Additionally, a web build would be uploaded to a static site per pull requests, allowing developers to test their changes before merging. As we neared Steam release, I extended the pipeline to include CD, publishing the builds to Steam's beta and production branches. This greatly enhanced testing and accelerated development and testing.
