Once the fragment shader has processed the fragment, a so-called stencil test is executed. This has the ability to discard the fragments, just like the depth test. After that, the remaining fragments are passed to the depth test where OpenGL can discard more fragments.

## Stencil Buffer
The stencil test is based on the stencil buffer, which we can update during rendering. A stencil buffer contains 8 bits per stencil value that amounts to 256 different stencil values per pixel. We can set these stencil values to values of our liking and we can discard or keep fragments whenever a particular fragment has a certain stencil value.

> Each windowing library needs to set up a stencil buffer for you. GLFW does this automatically, so we don't have to tell GLFW to create one.

A simple example of a stencil buffer is shown below:

![[23-0.png]]

The stencil buffer is cleared with zeros, and then an open rectangle of 1s is stored in the stencil buffer. The fragments of the scene are then only rendered wherever the stencil value of that fragment contains a 1.

Stencil buffer operations allow us to set the stencil buffer at specific values wherever we're rendering fragments. By changing the content of the stencil buffer while we're rendering, we're *writing* to the stencil buffer. In the same or next frame, we can *read* these values to discard or pass fragments.

The general outline is:
- Enable writing to the stencil buffer.
- Render objects, updating the content of the stencil buffer
- Disable writing to the stencil buffer
- Render (other) objects, this time discarding certain fragments based on the content of the stencil buffer.

We can thus discard certain fragments based on the fragments of other drawn objects.

```c++
// to enable
glEnable(GL_STENCIL_TEST);
// to clear
glClear(GL_STENCIL_BUFFER_BIT);
```

Similar to `glDepthMask`, there is a `glStencilMask` that allows us to set a bitmask.

```c++
glStencilMask(0xFF); // each bit is written to as is
glStencilMask(0x00); // each bit ends up as 0 (disable)
```
