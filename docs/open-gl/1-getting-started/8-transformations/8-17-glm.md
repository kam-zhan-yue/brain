GLM stands for Open**GL** **M**athematics, and is a *header-only* library.

Let's try to translate a vector of `(1,0,0)` by `(1,1,0)`. 
```c++
glm::vec4 vec(1.0f, 0.0f, 0.0f, 1.0f); // define as a vec4 with homogeneous coordinate 1.0
glm::mat4 trans = glm::mat4(1.0f); // initialise an identity matrix
trans = glm::translate(trans, glm::vec3(1.0f, 1.0f, 0.0f)); // generate the translation matrix
vec = trans * vec; // apply the translation matrix
std::cout << vec.x << vec.y << vec.z << std::endl;
```

- We define a vector `vec` with the built-in vector class.
- Then we define a `mat4` and initialise it to the identity matrix
- Then we create a transformation matrix by passing our identity matrix to the `glm::translate` function, together with a translation vector
- The given matrix is then multiplied with a translation matrix and the resulting matrix is returned
- Then we multiply our vector by the transformation matrix and output the result

```c++
glm::mat4 trans = glm::mat4(1.0f);
trans = glm::rotate(trans, glm::radians(90.0f), glm::vec3(0.0, 0.0, 1.0));
trans = glm::scale(trans, glm::vec3(0.5, 0.5, 0.5));
```
- First we scale the container by 0.5 on each axis
- Then we rotate the container by 90 degrees around the z-axis
- GLM expects its angles in radians, so we convert the degrees to radian
- The axis that we rotate around should be a unit vector, so be sure to normalise the vector first if you're not rotating around the X, Y, or Z axes.
- Because we pass the matrix to each of GLM's functions, GLM automatically multiplies the matrices together, resulting in a transformation matrix that combines all the transformations.

In order to get the transformation matrix to the shaders, we need to adapt the vertex shader to accept a `mat4` uniform variable and multiply the position vector by the matrix uniform.

> GLSL also has `mat2` and `mat3` types that allow for swizzling-like operations just like vectors. All the aforementioned math operations are allowed on matrix types.

```glsl
uniform mat4 transformation;

void main() {
	gl_Position = vec4(aPos, 1.0f) * transformation;
	TexCoord = aTexCoord;
}
```

We added the uniform and multiplied the position with the transformation matrix before passing it to `gl_Position`.

```c++
unsigned int transformLoc = glGetUniformLocation(shader.ID, "transform");
glUniformMatrix4fv(transformLoc, 1, GL_FALSE, glm::value_ptr(trans));
```

- First query the location of the uniform variable and then send the matrix data to the shaders using `glUniform` with `Matrix4fv` as its post fix
- The first argument is the uniform location
- The second argument tells OpenGL how many matrices we'd like to send
- The third argument asks us if we want to transpose our matrix (to swap the columns and rows)
- OpenGL developers use an internal matrix layout called column-major ordering which is the default matrix layout in GLM, so there is no need to transpose the matrix.
- The last parameter is the matrix data, but GLM stores their data, so we need to convert using `value_ptr`

```c++
glm::mat4 trans = glm::mat4(1.0f);
trans = glm::translate(trans, glm::vec3(0.5, -0.5f, 0.5f));
trans = glm::rotate(trans, (float)glfwGetTime(), glm::vec3(0.0f, 0.0f, 1.0f))
```
The actual transformation order should be read in reverse: even though in code we first translate and then later rotate, the actual transformations first apply a rotation and then a translation.

Using transformations like this in the vertex shader saves us the effort of re-defining the vertex data and saves us some processing time since we don't have to re-send our data all the time.
